Case study 01 · Borrower application · Responsive web

Reframing the mortgage application as a conversation.

Transforming a high-friction, long-form application into a guided conversational journey, designed to evolve toward AI-assisted interactions.

Role
Principal Product Designer
Ownership
Product strategy, workflow planning, UX/UI, responsive prototype
Timeline
2026 · 2 months

The challenge

Too much paperwork. Zero feedback.

Mortgage applications ask borrowers for a large amount of information before giving much value in return. The legacy experience exposed that complexity through a traditional long-form interface, creating cognitive overload and significant abandonment.

What industry research shows

~1 in 2borrowers finished an online mortgage application in one sitting; the top reason for abandoning was that it took too longEllie Mae survey, 2019 ↗

The questions that shaped the work

Q1

Are all the up-front questions necessary?

Q2

Can some questions move later, when borrowers are more invested, to reduce drop-off?

Q3

How can we give more guidance during the process?

Q4

Can borrowers get something back even while we're still requesting information?

Q5

How do we break the application into bite-sized steps that don't overwhelm?

First-principles thinking

Shaking off the shadows of the past.

With competitors launching new loan application designs, it was clear that incremental improvements wouldn't regain loanDepot's position. The new application needed to be a step change, and built to last.

This is, however, a very conservative industry, and every change required lengthy discussion. To move those discussions forward, I built a lightweight web tool with an AI coding agent. It surfaced which questions and information tie to the milestones that matter most: lead generation and prequalification.

The tool

Loan Origination Planner

Instead of debating the flow in the abstract, stakeholders could shape the application directly and see what each change meant for lending milestones.

Structure the application

Stakeholders can add, edit, remove and reorder categories and individual questions, and move steps between categories.

Connect every question to a purpose

Each question maps to the requirement it satisfies, so the application stops accumulating questions just because they've always been there.

Visualize lending milestones

Requirements roll up into checklists that update as steps satisfy them, and the tool shows where each milestone is reached in the flow.

Instead of “Should we ask this?”

“What requirement does this answer satisfy?”

The design pivot

From lengthy forms to an interactive conversation.

MVP · Rules-based

Deterministic conversation

  • Answers trigger predefined follow-up questions
  • Conditional fields appear only when relevant
  • Steps are skipped based on established application logic
→
Next · AI-assisted

A virtual agent in the same interface

  • Controls pacing and keeps questions in context
  • Acknowledges responses
  • Follows up when answers are incomplete or unclear

AI capabilities weren't production-ready when the design was introduced, so the MVP used deterministic logic. The interface was built so a virtual agent could take over without a redesign.

That let us modernize the experience within organizational constraints and without extensive backend upgrades.

Outcome

A new interaction model, and a shared way to decide.

The concept established a new interaction model for the mortgage application: less visible complexity, an experience that adapts to the borrower, and a foundation for AI-assisted workflows.

Just as importantly, the planner gave the organization a shared framework for deciding what belongs in the application, when to collect it, and which requirement each step satisfies.
